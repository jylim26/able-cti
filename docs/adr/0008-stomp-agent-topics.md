# ADR-0008: 상태 푸시는 STOMP, 토픽은 상담원별로 나눈다

Status: Accepted
Date: 2026-08-18

## Context

지금까지 상담원 상태를 보는 방법은 REST 조회뿐이다.
상태가 바뀌는 순간을 클라이언트가 알 수 없다.
착신 팝업도, 상태 검증용 테스트 페이지도 서버가 밀어주는 채널이 필요하다.

결정할 것은 두 가지다.

> 어떤 프로토콜로 밀어주는가? 주소(토픽)는 어떻게 나누는가?

## Decision

### 프로토콜은 STOMP

WebSocket 위에 STOMP를 얹는다. Spring 내장 simple broker를 쓴다.

| 후보 | 평가 |
|---|---|
| 순수 WebSocket | 구독·주소 개념이 없어서 "상담원별 채널"을 직접 구현해야 한다 |
| STOMP + simple broker | 구독/발행이 내장. Spring 지원이 기본값이라 코드가 가장 적다 |
| STOMP + 외부 브로커 (RabbitMQ 등) | 와일드카드 구독, 다중 인스턴스 지원. 지금 규모에 과하다 |

### 토픽은 상담원별

    /topic/agents/{loginId}

상태가 바뀐 상담원의 토픽으로만 보낸다. 키는 login_id다 ([ADR-0007](0007-user-extension-mapping.md)).

전체를 한 토픽으로 브로드캐스트하는 안과 비교했다.

| | 브로드캐스트 하나 | 상담원별 토픽 |
|---|---|---|
| 테스트 페이지 (전체 뷰) | 구독 한 번 | 상담원마다 구독해야 한다 |
| 상담원 화면 (자기 것만) | 남의 상태까지 받고 클라이언트가 거른다 | 자기 토픽만 받는다 |
| 착신 팝업 (그 사람에게만) | 못 쓴다. 별도 토픽 필요 | 그대로 쓴다 |

최종 소비자는 상담원 화면이고, 착신 팝업(로드맵 4)까지 같은 주소를
쓸 수 있어서 상담원별 토픽으로 간다. 테스트 페이지의 상담원별 구독은
개발 도구가 감수한다. simple broker는 와일드카드 구독이 없어서
전체 뷰가 필요해지면(감독 화면 등) 그때 브로드캐스트 토픽을 추가한다.

### 보내는 것은 상담원 스냅샷

상태가 바뀔 때마다 그 상담원의 현재 전체 상태를 보낸다.
"무엇이 바뀌었다"(델타)가 아니라 "지금 이렇다"(스냅샷)다.
클라이언트는 마지막 메시지를 그리기만 하면 되고,
메시지 하나를 놓쳐도 다음 메시지가 전체를 덮어쓴다.

### 발행 경로는 Spring 이벤트

`agent` 모듈이 상태 변경 때 `AgentStateChangedEvent`를 발행하고,
`push` 모듈이 구독해 STOMP로 내보낸다 ([ADR-0006](0006-spring-events-between-modules.md)).
`agent` 모듈은 WebSocket을 모른다.

## Consequences

- 클라이언트는 REST로 현재 상태를 읽고, 토픽 구독으로 변화를 따라간다.
- STOMP 전송은 브로커 채널에 넘기는 것까지라 AMI 리더 스레드에서
  발행해도 된다. `sendAction`처럼 응답을 기다리지 않는다.
- simple broker는 인스턴스 하나짜리다. 서버를 여러 대로 늘리면
  외부 브로커로 바꿔야 한다.
- 인증 없는 구독이다. 누구나 아무 토픽이나 구독할 수 있다.
  인증은 사용자 인증 체계가 생길 때 같이 넣는다.
